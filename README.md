# ใบงานปฏิบัติการที่ 1: ชนิดข้อมูล หน่วยความจำ และการวัดประสิทธิภาพ
**โครงสร้างข้อมูล (Data Structure)**

---

## กิจกรรมที่ 1: ขนาดและช่วงค่าของชนิดข้อมูล

### 1.1 ผลการทดสอบขนาดด้วย sizeof
- `char`: 1 ไบต์
- `short`: 2 ไบต์
- `int`: 4 ไบต์
- `long`: 4 ไบต์ หรือ 8 ไบต์ (บน 64-bit Linux)
- `long long`: 8 ไบต์
- `float`: 4 ไบต์
- `double`: 8 ไบต์
- `int*`: 8 ไบต์ (ระบบ 64-bit)

### 1.2 ค่าคงที่ขีดจำกัด
- `INT_MIN`: -2147483648
- `INT_MAX`: 2147483647
- `UINT_MAX`: 4294967295
- `FLT_DIG`: 6
- `DBL_DIG`: 15

### 1.3 สรุปผล unsigned char wrap-around
เมื่อบวกค่า `unsigned char` เกิน 255 (255 + 1) ค่าจะวนกลับมาเริ่มต้นที่ `0` ใหม่ ตามหลักการ Wrap-around (Modulo 256)

## กิจกรรมที่ 2: ที่อยู่และลำดับไบต์
- สถาปัตยกรรมเครื่องเป็นแบบ **Little-endian** เนื่องจากไบต์ที่มีนัยสำคัญต่ำสุด (LSB: `78`) ถูกจัดเก็บไว้ที่ตำแหน่งที่อยู่หน่วยความจำต่ำสุด
- ที่อยู่ของ `a[0]` กับ `a[1]` ห่างกัน 4 ไบต์ ซึ่งสอดคล้องกับ `sizeof(int)`
- ตัวแปรเดี่ยว `c`, `i`, `d` ถูกจัดวางตาม Memory Alignment ของคอมไพเลอร์

## กิจกรรมที่ 3: ความซับซ้อนเชิงเวลา ADT IntList
| การดำเนินการ | Big-O | เหตุผล |
| :--- | :---: | :--- |
| `list_init` | O(1) | กำหนดค่า size = 0 เพียงขั้นตอนเดียว |
| `list_append` | O(1) | เข้าถึงช่องท้ายสุดตามดรรชนีได้ทันที |
| `list_get` | O(1) | เข้าถึงข้อมูลตามตำแหน่ง i ได้โดยตรง |
| `list_sum` | O(N) | ต้องวนลูปอ่านสมาชิกครบทุกตัวเพื่อบวกค่า |
| `list_find` | O(N) | กรณีแย่สุดต้องค้นหาตั้งแต่ตัวแรกถึงตัวสุดท้าย |
| `list_remove_last` | O(1) | ลดขนาด size ลง 1 ได้โดยไม่ต้องเคลื่อนย้ายข้อมูล |

## กิจกรรมที่ 4: ตอบคำถามท้ายกิจกรรม

1. **อัตราการเติบโตของ time ใน `count_even_pairs`**: 
   เมื่อ $N$ เพิ่มขึ้นเป็น 2 เท่า เวลาเพิ่มขึ้นประมาณ 4 เท่า สอดคล้องกับความซับซ้อนเชิงเวลา $O(N^2)$
2. **การปรับปรุงการวัดเวลา `sum_all`**: 
   สาเหตุเพราะ $O(N)$ ทำงานเร็วมากจนเกินความละเอียดของ `clock()` แก้ไขได้โดยการเพิ่มขนาด $N$ ให้ใหญ่ขึ้นมาก ๆ หรือทำลูปเรียกใช้งานซ้ำ 1,000 รอบแล้วหารเวลารวม
3. **ผลกระทบจากการนำไปรันบนเครื่องที่เร็วกว่า**: 
   ผลการวิเคราะห์ Big-O **ไม่เปลี่ยนแปลง** เนื่องจาก Big-O วัดอัตราการเติบโตเชิงทฤษฎีตามขนาดข้อมูล $N$ ไม่ได้ขึ้นกับความเร็วของฮาร์ดแวร์
4. **แนวคิดอัลกอริทึม O(N) สำหรับนับคู่ผลบวกเลขคู่**:
   วนลูป 1 รอบเพื่อนับจำนวนเลขคู่ ($E$) และเลขคี่ ($O$) จากนั้นคำนวณจำนวนคู่ด้วยสูตร $\frac{E(E-1)}{2} + \frac{O(O-1)}{2}$ จะได้คำตอบในเวลา $O(N)$
